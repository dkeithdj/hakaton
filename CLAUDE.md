# Hakaton

Event platform for running a hackathon: admin setup, team workspaces, live timer, time-gated audience voting, and a public status page. One Cloudflare Worker serves both the Hono API and the React SPA. Product requirements and deploy steps are in `README.md`.

## Commands

```sh
npm run dev                # Vite + Workers runtime (Cloudflare Vite plugin)
npm test                   # API tests (Workers runtime), then page smoke tests (jsdom)
npm run typecheck          # wrangler types && tsc -b
npm run build              # typegen + typecheck + vite build
npm run db:migrate:local   # apply D1 migrations to the local database
npm run db:seed:local      # replace resources and prompts with seeds/production.sql
npm run deploy             # build, then wrangler deploy
```

Run one suite: `npx vitest run` (API) or `npx vitest run --config vitest.ui.config.ts` (UI).

First-time setup: `cp .dev.vars.example .dev.vars`, then `npm run db:migrate:local`. The local admin password is `admin`.

## Layout

| Path | Contents |
| --- | --- |
| `worker/index.ts` | Hono app: sessions, public state, voting, judging, `/api/participant/*`, `/api/admin/*` |
| `worker/resources.ts` | `RESOURCES` table: field definitions driving generic CRUD and validation for the admin-editable tables |
| `worker/settings.ts` | Key/value settings stored in D1, merged over `DEFAULT_SETTINGS` |
| `shared/types.ts` | Types and upload limits shared by the Worker and the client |
| `src/pages/` | One file per route: `Viewer` (`/`), `Participant`, `Vote`, `Judge`, `Admin`, `Privacy` |
| `src/components/` | App components; `ui/` holds shadcn components |
| `src/lib/api.ts` | `api()` fetch wrapper, `ApiError`, `useEventState` polling hook |
| `migrations/` | D1 migrations, applied in numeric order |
| `seeds/` | Event content run by hand with `db:seed:*`; replaces resources and prompts |
| `test/` | API tests under `@cloudflare/vitest-pool-workers` |
| `test-ui/` | Page smoke tests under jsdom |

## Architecture

- `wrangler.jsonc` routes `/api/*` to the Worker first; every other path falls back to the SPA.
- Bindings: `DB` (D1), `UPLOADS` (R2). Secrets: `ADMIN_PASSWORD`, `SESSION_SECRET`.
- Auth uses signed cookies. `session` carries the role (`admin` or `participant`) and team id; `voter` identifies a browser for one-ballot-per-voter. `requireRole()` guards the `participant` and `admin` sub-apps, and `assertTeamAccess()` keeps a team inside its own workspace.
- Participant access starts closed. The `participantAccess` setting gates team sign-in and every `/api/participant/*` route for teams (403 while closed); admins still get through. The admin flips it with `POST /api/admin/participants/open` or `close` from the Control tab. Closing keeps team sessions valid. While closed, `/participant` shows a preview with the presentation guidelines and the toolbox from the public `GET /api/tools`.
- `/api/*` has CSRF protection, so non-GET requests need an `Origin` header. The test client in `test/api.test.ts` sets one.
- Errors are thrown as `HTTPException` (see `bad()`) and returned as `{ error }` JSON by `app.onError`.
- Admin CRUD goes through `/api/admin/resources/:resource`. To make a new table editable, add an entry to `RESOURCES` instead of writing new routes.
- Uploads are multipart: create, `PUT` each part, then complete. Objects live in R2 and metadata in D1.
- Clients poll `/api/state` and apply `clockOffset` so countdowns follow server time.
- Judges are a `RESOURCES` entry the admin manages. A judge signs in at `/judge` by typing their name, with no password, and a separate signed `judge` cookie holds the judge id. Each judge scores a team on the criteria in `JUDGE_CRITERIA` (pitch 25, demo 40, impact 35). Judging is not tied to the voting window: `PUT /api/judge/scores` works until results are published.
- The final score is 80% average judge total (out of 100) and 20% audience average (out of 5), computed by `finalScore()` in `shared/types.ts`. Publishing requires every judge to have scored every team.
- `DELETE /api/admin/participant-data` is the after-event purge: it clears members, project titles, goals, progress, judge names, and all uploads, keeping team names, votes, and judge scores. `src/pages/Privacy.tsx` describes this, so update the policy when what is stored or deleted changes.
- While voting is open, the public state exposes only the number of ballots. Once results are published, everyone gets each team's final score only. The judge and audience averages behind it, judge names, and per-judge scores go only to the admin.

## Conventions

- Schema changes go in a new numbered file in `migrations/`; never edit an applied migration.
- `worker-configuration.d.ts` is generated by `wrangler types` and gitignored. Regenerate it after changing bindings in `wrangler.jsonc`.
- Client code imports from `@/` (aliased to `src/`); shared types are imported by relative path from `shared/types`.
- Add shadcn components with `npx shadcn add <name>` (style `radix-nova`, lucide icons). Tailwind v4 is configured in `src/index.css`, with no `tailwind.config`.
- `.githooks/pre-commit` runs `npm run typecheck` and `npm test` before every commit. `npm install` enables it by pointing `core.hooksPath` at `.githooks`.
- API behavior changes need a test in `test/api.test.ts`; page changes need one in `test-ui/pages.test.tsx`.

## graphify

This project has a knowledge graph at graphify-out/ with god nodes, community structure, and cross-file relationships.

Rules:
- For codebase questions, first run `graphify query "<question>"` when graphify-out/graph.json exists. Use `graphify path "<A>" "<B>"` for relationships and `graphify explain "<concept>"` for focused concepts. These return a scoped subgraph, usually much smaller than GRAPH_REPORT.md or raw grep output.
- If graphify-out/wiki/index.md exists, use it for broad navigation instead of raw source browsing.
- Read graphify-out/GRAPH_REPORT.md only for broad architecture review or when query/path/explain do not surface enough context.
- After modifying code, run `graphify update .` to keep the graph current (AST-only, no API cost).
